### Boundaries that require explicit decisions

- **CORR-INCOMPLETE-CASE-HANDLING, CORR-STATE-TRANSITION, CORR-CONTEXT-PROPAGATION**: Refine broad mechanisms using existing per-candidate training evidence; separate supported alternatives and actual state/context contracts from features and coordinated interfaces.
- **CORR-NEWLINE-ROUNDTRIP, SEC-TEMPLATE-SANDBOX, SEC-REDACTION-KEY-MATCH**: No current assistant-supported training cases. Resolve evidence/eligibility or retain explicit tentative/unresolved status; do not promote based on parent support.
- **CORR-SERIALIZER-SCALAR-CONTRACT, CORR-SCALAR-REPRESENTATION-CONTRACT**: Same parent, opposite interface direction. Retain leaf-specific expected result and never call the fixes equivalent.
- **SEC-HTTP-METHOD-RESTRICTION, SEC-CSRF-REQUEST-BINDING, SEC-CORS-ORIGIN-BOUNDARY**: Do not transfer complete CSRF protection, response-read access or mutation reachability between distinct browser-boundary mechanisms.
- **SEC-SECRET-COMPARISON-TIMING, SEC-RSA-PADDING-ORACLE**: After-code constant-time properties remain unproven; preserve conditional negative scope and actual runtime/protocol observability.

No current supported training cases for: `CORR-BYTES-TEXT-CONTRACT`, `CORR-INDEXER-DIMENSION-VALIDATION`, `CORR-LOOKUP-VALIDATION`, `CORR-NEWLINE-ROUNDTRIP`, `SEC-REDACTION-KEY-MATCH`, `SEC-TEMPLATE-SANDBOX`.
Parent support must not be used to promote these leaves or their ambiguous candidates.
